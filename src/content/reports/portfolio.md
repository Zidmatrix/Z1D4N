# Z!DVN / Technical Portfolio

## Summary

A personal technical portfolio centered on cybersecurity, supported by networking, operating systems, programming and university work. The site separates factual content from presentation and uses static hosting without a backend.

## Problem / Objective

Help a recruiter or technical reviewer understand my current stage and inspect actual work without confusing training, certification and professional experience.

## Scope and Environment

React, TypeScript and Vite. JSON stores factual records; Markdown stores reports and journal entries. The build produces static files for the GitHub Pages project path `/Z1D4N/`.

## My Contribution and AI Assistance

I supplied my identity, education, reported certifications, technical background and the portfolio requirements. AI assisted the design, implementation, content editing, repository inspection and test preparation. My personal review and ability to explain the implementation remain separate steps; this site does not claim that I independently wrote all its code.

## Tools and Why They Were Used

- React organizes reusable interface components.
- TypeScript catches integration mistakes before publishing.
- Vite produces a small static deployment.
- Native dialogs and hash links support keyboard interaction and direct links without a server router.
- Self-hosted fonts remove runtime third-party font requests.
- Playwright and axe check interaction, responsive layout and accessibility.

## Implementation Steps

1. Review supplied facts and the public GitHub sources.
2. Separate professional certifications from course completion and training.
3. Build responsive sections, project filtering and Markdown reading.
4. Add a minimal-permission GitHub Actions build and deployment workflow.
5. Validate content, types, the production build and browser behavior.

## Evidence and Results

The source, test suite and deployment workflow are included in this project. Actual validation and remote publication outcomes are recorded in `docs/PROJECT_LOG.md` and `docs/QA.md`; a workflow file alone does not prove successful deployment.

## Limitations

Issuer verification links, detailed IT Gate training information and specific lab artifacts have not yet been supplied. The owner-supplied technical CV is available as its original PDF in the Contact section. The old sales portfolios remain untouched. There is no simulated contact form, fabricated CV, skill percentage or invented employment history.

## Remediation and Retesting

Run the build and browser suite after content or design updates. Review the deployed GitHub Pages site after each deployment; local checks alone do not establish live readiness.

## Lessons / Next Review

Make claims specific enough to be checked. Add sanitized project evidence and review one technical explanation each week. Update the project log when new materials arrive.
